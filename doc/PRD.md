# 成交量异动扫描工具 PRD

## 1. 产品定位
一款面向A股投资者的成交量异动扫描工具，用于从目标板块（上证/深证/创业板）中快速筛选出**放量上涨**的股票，辅助发现市场资金异动信号。

## 2. 用户场景
- 盘后复盘：扫描当天或近期放量股票，寻找异动标的
- 选股辅助：从数千只股票中快速过滤出满足放量条件的候选股
- 量化研究：作为量化策略的信号输入源

## 3. 核心功能
- **全市场扫描**：多线程并行扫描目标板块所有股票
- **单股检测**：对指定股票代码进行放量检测
- **结果导出**：扫描结果自动保存为带时间戳的 txt 文件
- **结果展示**：按放量倍数降序打印到终端

## 4. 检测逻辑

### 4.1 数据分段
取每只股票最近 `AVG_DAYS + CHECK_DAYS` 个交易日的成交量数据，分为两段：
- **基期**：前 `AVG_DAYS` 天（默认 22 天）
- **检查期**：后 `CHECK_DAYS` 天（默认 2 天）

### 4.2 逐日对比规则
检查期每一天，与基期每一天做逐日对比：
```
比值 = 检查期该日成交量 / 基期各日成交量
```
统计满足以下条件的基期天数：
```
MULTIPLIER_MIN ≤ 比值 < MULTIPLIER_MAX
```
（MULTIPLIER_MAX = 0 时无上限）

### 4.3 通过判定
- 检查期单天通过：满足条件的基期天数占比 ≥ `PASS_RATIO`（默认 80%）
- 整体触发信号：检查期所有天都通过

### 4.4 中位倍数
展示该检查期日与基期所有天比值的**中位数**，作为该日放量程度的代表值。

## 5. 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `CHECK_DAYS` | 2 | 检查期天数，最近 N 天都要满足条件 |
| `AVG_DAYS` | 22 | 基期天数，用于逐日对比的参考窗口 |
| `MULTIPLIER_MIN` | 1.8 | 放量下限，比值需 ≥ 此值 |
| `MULTIPLIER_MAX` | 0 | 放量上限，0 = 不设上限 |
| `PASS_RATIO` | 0.8 | 通过率阈值，至少 80% 的基期日满足条件 |
| `SCAN_SH_MAIN` | False | 是否扫描上证主板 |
| `SCAN_SZ_MAIN` | False | 是否扫描深圳主板 |
| `SCAN_CHI` | True | 是否扫描创业板 |
| `EXCLUDE_ST` | True | 排除 ST / *ST 股票 |
| `EXCLUDE_SUSPENDED` | True | 排除停牌股（最近 5 天成交量全为 0） |
| `MIN_AVG_VOLUME` | 0 | 最低基期日均成交量（万手），0 = 不过滤 |
| `WORKERS` | min(10, CPU-1) | 并发线程数 |
| `MAX_RETRIES` | 2 | 网络请求失败重试次数 |

## 6. 过滤条件（按顺序执行）
1. 排除 ST / *ST 股票（可配置）
2. 排除停牌股（可配置）
3. 基期数据不足 `AVG_DAYS + CHECK_DAYS` 条 → 跳过
4. 基期日均成交量低于 `MIN_AVG_VOLUME` → 跳过

## 8. 数据源
- **来源**：[akshare](https://github.com/akfamily/akshare) 开源库
- **底层**：东方财富 push2his.eastmoney.com HTTP 接口
- **免费、无需注册**
- **数据时效**：盘中可获取当日实时数据，更新频率优于 baostock

## 9. 技术实现
- **并发模型**：`ThreadPoolExecutor` 多线程（HTTP IO 密集型）
- **核心计算**：numpy 向量化矩阵运算（逐日对比）
- **重试机制**：单只股票请求失败最多重试 2 次
- **进度反馈**：每 200 只打印一次进度

## 10. 使用方式

```bash
# 全板块扫描（按配置区的板块开关）
python stock_volume.py scan

# 单股检测（默认查 300750）
python stock_volume.py single
python stock_volume.py single 301302
```

## 11. 已知限制
- akshare 基于爬虫，网络不稳定时部分股票可能查询失败
- 数据源更新有延迟，非严格实时行情
- 无缓存机制，每次扫描都重新拉取全量数据
