# A 股成交量异动扫描工具 — 程序逻辑文档

> 对应源文件：`stock_volume.py`

---

## 一、程序概述

本工具用于从 A 股市场中筛选出近期成交量显著放大的股票，支持单股检测和全市场批量扫描两种模式。

**依赖**：`akshare`、`pandas`、`numpy`

---

## 二、运行模式

| 模式 | 启动方式 | 功能 |
|------|---------|------|
| **单股检测** | `python stock_volume.py` | 检测单只股票是否放量（默认检测 300750） |
| **指定股票** | `python stock_volume.py single 600519` | 检测指定代码的股票 |
| **全市场扫描** | `python stock_volume.py scan` | 多线程扫描整个板块，批量筛选放量股 |

---

## 三、核心算法 —— 放量检测逻辑

核心函数：`check_volume_surge(df)`

### 3.1 时间段划分

```
时间线: ────────[  基期 22天  ]────[ 检查期 2天  ]─→
                ← AVG_DAYS →     ← CHECK_DAYS →
```

- **基期**：取最近 `CHECK_DAYS` 天之前的 `AVG_DAYS` 个交易日，作为成交量基准
- **检查期**：取最近 `CHECK_DAYS` 个交易日，逐日判断是否放量

### 3.2 逐日对比逻辑

对检查期的**每一天**，与基期的**每一天**计算比值：

```
比值 = 检查期该日成交量 / 基期各日成交量
```

使用 numpy 向量化运算，一次性生成 `(检查期天数, 基期天数)` 的比值矩阵。

### 3.3 通过率判定

统计比值 ≥ `MULTIPLIER_MIN` 倍的基期天数占比：

- 占比 ≥ `PASS_RATIO`（80%）→ 该检查日判定为**放量**
- 占比 < `PASS_RATIO` → 该检查日判定为**未放量**

> **为什么用通过率而不是简单均值对比？**
> 通过率方式逐日对比，可以容忍基期中少量异常高值（如偶发大单）的干扰，比均值对比更稳健。

### 3.4 整体信号

检查期**所有天都放量**，才判定该股票触发「放量信号」。

### 3.5 举例

检查期某天成交量 100 万手，基期 22 天中有 20 天成交量 < 55.6 万手（100 ÷ 1.8），则 20/22 ≈ 91% > 80%，该天判定为放量。

## 四、全市场扫描数据流

```
get_all_stocks()            ← 从 akshare 拉取全 A 股列表
       ↓                       按板块过滤（当前只开了创业板）
  股票列表 [1000+只]
       ↓
  ThreadPoolExecutor          ← 多线程（10 个 worker）并行扫描
       ↓
  _worker(每只股票)            ← 逐只处理
    ├─ 排除 ST 股               （EXCLUDE_ST=True）
    ├─ _query_stock_volume()   ← 调 akshare API 拉历史数据（带重试）
    ├─ 排除停牌股               （最近5天成交量全0）
    ├─ check_volume_surge()    ← 执行放量检测
    └─ 返回命中结果 or None
       ↓
  汇总结果 → 按最大倍数降序排列
       ↓
  _print_results()            ← 终端表格输出
  _save_results()             ← 保存到 txt 文件（scan_板块_时间戳.txt）
```

## 五、关键配置项

| 配置 | 默认值 | 含义 |
|------|--------|------|
| `CHECK_DAYS` | 2 | 检查期天数：最近 N 天是否放量（N 天都需满足） |
| `AVG_DAYS` | 22 | 基期天数：取检查期之前的 N 天作为对比基准 |
| `MULTIPLIER_MIN` | 1.8 | 放量下限：检查期成交量需达到基期的 N 倍 |
| `MULTIPLIER_MAX` | 0 | 放量上限：0 表示不设上限 |
| `PASS_RATIO` | 0.8 | 通过率：战胜基期 80% 的天数即可，容忍异常值 |
| `SCAN_SH_MAIN` | False | 是否扫描上证主板（排除科创板 688/689） |
| `SCAN_SZ_MAIN` | False | 是否扫描深圳主板（000/001 开头） |
| `SCAN_CHI` | True | 是否扫描创业板（300/301 开头） |
| `EXCLUDE_ST` | True | 排除 ST / *ST 股票 |
| `EXCLUDE_SUSPENDED` | True | 排除停牌股（最近 5 天成交量全为 0） |
| `MIN_AVG_VOLUME` | 0 | 最低基期日均成交量（万手），0 表示不过滤冷门股 |
| `WORKERS` | min(10, cpu-1) | 并发线程数 |
| `MAX_RETRIES` | 2 | 单只股票请求失败时的重试次数 |
| `EXTRA_DAYS` | 10 | 查询历史数据时多取的自然日（覆盖周末/节假日） |

## 八、设计要点

1. **向量化对比**：使用 numpy 广播机制，一次生成完整的比值矩阵，避免 Python 循环，性能高
2. **通过率而非均值**：逐日对比 + 通过率阈值，比简单均值对比更抗异常值干扰
3. **多线程并行**：akshare 请求为 IO 密集型，10 线程并发可大幅缩短全市场扫描时间
4. **重试机制**：网络请求最多重试 2 次，增强鲁棒性
5. **多层过滤**：ST 排除 → 停牌排除 → 冷门股排除，减少误报
